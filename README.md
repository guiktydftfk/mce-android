# MCE 星光班 · Android 原生客户端

> 面向 Discuz! X3.5 论坛 [mce.msi.cn](https://mce.msi.cn) 的原生 Android 客户端。
> Kotlin + Jetpack Compose，无 WebView（纯原生抓取与解析），支持自动更新。

**当前版本：`0.3.2`（versionCode 36）**

## 📦 下载即安装

1. GitHub 页面点 **Code → Download ZIP**
2. 解压后，仓库**根目录**的 `MCE-starlight.apk` 即安装包
3. 传到手机点击安装（首次需允许「安装未知应用」）

备用位置：`release/MCE-latest.apk`（自动更新下载用的同一个文件）
国内网络下载不便时，可用 `version.json` 里的 gh-proxy 地址。

## 🔧 构建

工程使用本地化工具链（不依赖系统安装）：

```powershell
# 一键构建（自动 +0.0.1 版本，输出 dist/ 并复制到桌面）
powershell -ExecutionPolicy Bypass -File scripts/build-apk.ps1 -Bump -ToDesktop
```

- 工具链位置：`../android-dev/{jdk,sdk,gradle,gradle-home}`；已配置 `android.overridePathCheck=true`（中文路径）与 Kotlin in-process 编译。
- **0.3.2 起发行包改为 `assembleRelease` + R8（`isMinifyEnabled`/`isShrinkResources`）**：APK 从 ~9.9MB 降到 ~1.7MB，冷启动更快；release 用仓库内 `keystore/debug.keystore`（与历史 debug 包同签名，可覆盖升级），R8 规则见 `app/proguard-rules.pro`。

## 🔄 自动更新机制

- 清单：仓库根目录 `version.json`（`versionName` / `versionCode` / `notes` / `apk`）
- 镜像优先级：`gh-proxy` → `fastly.jsdelivr` → `gcore.jsdelivr` → `raw.githubusercontent`（国内实测可达性排序）
- 清单请求带时间戳绕过 CDN 缓存；失败会明确提示，不再误报「已是最新」
- 下载：APK 经 gh-proxy，失败回退直连；完成后拉起系统安装器
- 暂停：设置内可暂停 7 / 15 天

## 🐞 问题自查（无需连电脑）

- **自检报告**：设置 → 诊断 → 自检报告（版本/设备/登录态/设置/最近抓取页面，一键复制）
- **图片自检**：设置 → 诊断 → 图片自检，输入帖子 ID，逐张探测图片请求（状态码/Content-Type/是否返回 HTML）
- **开发者**：抓取过的页面会落盘到应用私有目录，可 `adb shell run-as cn.mce.starlight cat files/debug_xxx.html` 查看原始 HTML

## ⚠️ 已知限制

- 普通应用无法完全静默安装：系统安装器需用户点一次「安装」（Android 安全限制）
- 门户资讯（`portal.php`）、活动发帖、附件（非图片）上传尚未实现（投票发帖 0.3.2 已支持）
- **用户搜索**（搜用户）在论坛手机模板缺失 `mytpl/menubottom.htm` 时服务端会 503：客户端已内置电脑版模板回退，可正常使用；根治需论坛后台补模板文件

## 0.2.3 · 解析时机审计 + 自动更新

### 修复「解析时机」类问题（逐个定位）
- **回帖后显示“没有解析到楼层内容”**：POST 响应是提示/跳转页，不能当帖子页解析 → 改为回帖成功后重新 GET（带时间戳绕过缓存），失败再重试一次，仍失败提示手动刷新
- **登录态误判（明明登录却当游客 / 莫名弹登录框）**：
  - 根因1：网络失败被当成未登录并清除本地登录态 → 只有「确实取到登录页」才判定游客，超时保持现状
  - 根因2：资料页移动版标题不是「X的个人资料」，旧判定把已登录误判为游客 → 改用 `spacecp`/退出链接等证据
  - 根因3：`WebCookies` 把 CookieJar 与旧 CookieManager 的同名 Cookie 拼接，游客 `auth/saltkey` 覆盖新会话 → 改为 **只以 CookieJar 为准**
  - 根因4（关键）：Discuz 登录 Cookie 下在**302 跳转响应**里，`HttpURLConnection` 自动跟随只暴露最终响应头 → 丢 Cookie。改为**手动跟随 3xx、逐跳保存 Set-Cookie**
- **列表缩略图时机问题**：失败结果不再永久缓存；且改用完整解析器（含 `.attach_list` 相册/附件图）
- **发帖页表单加载时机**：登录态变化或失败后可重试，不再永久卡在“可能未登录”
- **加载更多与刷新并发**：刷新过程中禁止触发 loadMore，避免重复/错乱
- **刷新语义**：点刷新/下拉刷新时**先回到最顶部**再刷新

- 启动时自动检查仓库 `version.json`（失败回退 GitHub Releases API）

## 架构说明

- 绞杀者模式：内容页逐屏从 WebView 替换为原生 Compose
- 数据层：`HttpForumRepository` 携带移动 UA 抓取 Discuz 触屏模板，Jsoup 解析
- 会话层：WebView 的 Cookie 由 `CookieManager` 保存，原生请求带同一个 Cookie 头
- 兜底：任何原生页解析失败都能一键切「网页版」
